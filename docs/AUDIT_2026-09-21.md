# MLBComp adversarial audit — 2026-09-21

## Scope

This pass checks the implementation against the autonomous MLB research and
paper-trading requirements. It was run against the repository checkout without
assuming that ignored raw data exists.

## Findings and fixes

- The static site is now generated only by `mlbcomp.web.export_static`.
  It does not contain a random-data generator or fabricated order book.
- A 68-entry strategy library is persisted with immutable version metadata.
  It covers regular-season and postseason hypotheses, all four postseason
  rounds, and the requested market families. Unsupported inputs are visibly
  `DATA_UNAVAILABLE` rather than estimated.
- `REG`, `POST`, `WC`, `DS`, `LCS`, `WS` and `ALL` are explicit environments.
  Postseason models include transfer, adjusted, dedicated, series-state,
  round-specific and hierarchical slots; no superiority is assumed.
- SQLite now contains normalized source, observation, baseball, feature,
  market, quote, prediction, forward-test, position, settlement, issue,
  experiment and audit tables.
- Paper wagers require a verified timestamped observed quote. Missing quotes
  become EVAL/PROPOSED records with no price, stake, fill, liquidity or PnL.
- `immutable_ledger` is SHA-256 hash chained and protected by update/delete
  triggers. Corrections are append-only records.
- The source registry records availability, access, cost, restrictions,
  licensing, granularity, automation, verification date and limitations.
- The static projection now reports `NO_SOURCE_SNAPSHOT` when raw/features are
  absent. It does not claim games, odds, results, PnL, Kalshi trades or
  performance that cannot be reproduced in this checkout.
- Eighteen adversarial controls are written by `verify.checks` and surface in
  the website.

## Current evidence boundary

No ignored `data/raw/`, `data/features/` or database source snapshot is shipped
with this commit. Consequently the committed JSON contains strategy metadata,
source discovery records, research `DATA_UNAVAILABLE`/`NOT_RUN` rows and audit
controls, but zero wager records. That is an intentional safety state, not a
failed backtest.

To create a result-bearing snapshot, run the explicit source fetcher, validate
content and licensing, ingest, backtest, run research, run checks and export.
If any source or quote gate fails, the affected result remains unavailable.
